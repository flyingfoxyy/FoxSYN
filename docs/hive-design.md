# hive — 局部复杂逻辑团发现器（设计 spec）

**日期**：2026-08-08
**状态**：设计已批准，待写实现计划
**定位**：映射后 LUT 网表上的只读测量命令，输出「接口窄、内部胖」的候选区域清单

---

## 1. 目标与非目标

### 背景

FoxSYN 现有的分区类命令都在做**全局平衡划分**（`hpart` 调外部 hmetis/patoh，`fmpart` 提供模板化 FM），下游的 `csr*` / `cpr` / `cmfs` / `pdecomp` 则在已分区的网表上做局部手术。这条链缺一个环节：**主动去网表里找那些「对外连接少、内部逻辑节点多」的局部区域**。

这类区域的价值在于它是深度逻辑优化的天然靶子——外部接口窄意味着这块逻辑的功能可以用少量变量描述，而内部节点多意味着当前实现可能远离最优。`if -K` 的 cut 枚举只看单输出、叶子数 ≤ K 的锥，看不见「12 个输入、2 个输出、内部 40 个 LUT」这种形状。

`hive`（蜂巢：内部密集、入口窄）就是这个发现器。

### 目标

在 `src/hive/` 下提供 ABC 命令 `hive`，在当前逻辑网络上找出 Top-N 个候选逻辑团，输出报表：每个团的内部节点数、输入数、输出数、密度评分、LUT 数下界、层带范围。

### 非目标

- **不做重综合**。`hive` 只发现和度量，不抽子网表、不重映射、不改网表。真实收益测量（抽出区域实跑 `collapse` / `if` 对比 LUT 数）是下一期。
- **不写回 `Pdb`**。`hive` 不产生分区，输出是一份候选清单而非划分方案。
- **不要求全网覆盖**。绝大多数节点不属于任何报出的团——「平坦地带」就是不报。
- **不做重叠候选池**。报出的团之间不允许高度重叠（Jaccard 受阈值限制，见 §4.5），但**不保证完全不相交**——阈值以下的部分重叠是允许的。下游若需要互斥集合，需自行取舍。
- **不消费分区信息**。`hive` 可以在 `hpart` 之前跑，不需要 `pPdb`。

### 与「先测量后实现」的关系

这一期的交付形态与 `csr3` / `csr4` 的方法论一致：先造仪器读数，用数据决定要不要投实现。区别是 `csr3`/`csr4` 测的是「一束割线浪费了多少编码位」，`hive` 测的是「网表里有多少块窄接口胖肚子的逻辑，以及它们离下界有多远」。

## 2. 度量口径

所有定义都必须先钉死，否则算法与报表无法互相校验。

### 2.1 顶点宇宙

**可成为区域成员的对象**恰好两类：内部节点（`Abc_ObjIsNode`，映射后即 LUT）与 `const1`。

以下对象永远是边界，不进区域：PI、PO、BI、BO、latch。

**`const1` 的三条规则**（必须一起读，否则会出现「允许吸收但永远选不中」的矛盾）：

1. 区域外的 `const1` **不计入 `in`**——常量不占子网表的输入引脚。
2. 区域外的 `const1` **仍然是合法的入口吸收候选**（见 §4.2）。候选集是「`R` 的全部区域外驱动对象中可吸收的那些」，不是「`in(R)` 的成员」——这两个集合因规则 1 而不同。
3. 区域内的 `const1` **不计入 `out`**，即使它有区域外的 fanout。理由见 §2.4：`out` 参与 LUT 下界推导，而常量输出不需要 LUT 实现。

latch 不需要像 `hpart` 那样被前置拒绝——`hive` 只读，latch 当边界处理即可。

### 2.2 边界计数

对区域 `R`：

- **`in(R)`** = `R` 外部、且驱动 `R` 内某个节点的**不同源对象**数。同一个 driver 供 3 条 fanin 边**只算 1**。
  - 理由：下游关心的是抽出子网表的**输入引脚数**，不是边数。这跟 `csr` 刻意选 cut-edge（因为每次 resub 只修一条边）是相反的取舍，因为这里的消费者不同。
  - PI、BO（latch 输出）、以及区域外的内部节点都可能是 `in` 成员；区域外的 `const1` 不计入（§2.1 规则 1）。
- **`out(R)`** = `R` 内、且至少有一个 fanout 落在 `R` 外的节点数（`const1` 除外，见 §2.1 规则 3）。驱动 PO 或 latch 输入（BI）也算「落在外面」。
  - 同理这是子网表的**输出引脚数**。
  - **一个节点同时有区域内与区域外 fanout 时只算 1 次**——它是一个输出信号，不是两个。这个节点既是区域输出又是区域内部信号，这一点让 §2.4 的槽位论证偏保守（少算了内部消费者），但不影响其正确性。增量维护必须保住这个语义：吸收它的某个区域外 fanout 后，只有当**全部** fanout 都进了区域，它才脱去 output 身份。
- **`B(R) = in(R) + out(R)`**：边界总引脚数
- **`N(R)`** = `R` 内的**内部节点数**，不含 `const1`。与 §2.4 里 `m` 的口径一致，两者都只数 LUT，`gap = N − LB` 才是同类相减。

### 2.3 排序目标

```
Q(R) = N(R) / B(R)
```

即「每个边界引脚摊到多少个内部节点」。

选它的理由是它有**真正的内部极值**：往开阔地生长通常加 1 个节点却加好几个引脚，`Q` 下降；而吸收一个「fanout 全在区域内」的 driver 则 `in` 减 1、`N` 加 1，`Q` 跳升。这个形状正是「窄腰胖肚」。

`Q` 是**唯一的排序键**。

### 2.4 LUT 数下界与 gap

设 LUT 宽度为 `K`（`-K`，默认 6）。

**下界只在一个明确的实现模型下成立，必须先把模型写死：**

> **M1（结构引脚保持）**：重实现必须读取区域的全部 `in` 个外部输入，且每个输出 `j` 仍依赖它当前的全部结构支撑 `supp_j`。
> **M2（LUT-only）**：每个区域输出都由一个 K-LUT 实现——不允许直连线、常量或缓冲器替代。
> **M3（无死逻辑）**：计数前区域内无不可达 LUT。

**槽位计数论证**（在 M1–M3 下）：设重实现用 `m` 个 K-LUT，共提供 `mK` 个输入槽。要消化的信号有两类：`in` 个外部输入（M1 保证每个至少被读一次），以及内部产生且被区域内消费的信号，后者至少 `m − out` 个（M3 保证非输出 LUT 必有区域内消费者）。于是：

```
mK ≥ in + (m − out)   ⟹   m(K−1) ≥ in − out
```

同一模型下再叠两条：`m ≥ out`（M2 保证每个输出各占一个 LUT），以及每个输出各自的单输出锥下界。

```
LB(R) = max( out,
             ⌈(in − out) / (K−1)⌉,          // (in − out) ≤ 0 时该项取 0
             max_j ⌈(supp_j − 1) / (K−1)⌉ )

gap(R) = N(R) − LB(R)
```

`supp_j` 是第 `j` 个输出节点在区域内的**结构支撑集**大小（沿区域内 fanin 反向可达、在区域边界处停止所触及的 `in` 成员数；区域外 `const1` 不计入）。

一个节点重复读同一个信号（fanin 表里出现两次）不影响论证——它多占一个槽，只让界更松。同理，既是区域输出又被区域内消费的节点会让 `m − out` 少算内部信号，同样只是让界更松。

`N(R)` 与 `m` 的计数口径一致：都只数 LUT。区域内的 `const1` 不计入 `N`。

### 2.5 gap 的定位：筛子，不是收益预测

必须诚实交代这个界的强度，包括一条会让人误用它的根本局限。

**局限一：M1 对功能性重综合不成立，所以 `gap` 不能当排除性筛子。** M1 要求「每个结构输入都得读」，但功能性优化恰恰可以证明某个输入是冗余的。反例（`K=2`）：

```
x = LUT(a, b)     // 真值表忽略 b
y = LUT(x, c)     // 真值表忽略 c，y 是唯一区域输出
```

结构上 `in=3`、`out=1`、`supp=3`，公式给 `LB = max(1, ⌈2/1⌉, ⌈2/1⌉) = 2`。但这个区域功能上只算 `a`，一个 LUT 就够（甚至一根线）。「无空悬 fanin」保证不了功能依赖性。

而 `hive` 的下游正是功能性重综合。所以：**`gap ≤ 0` 不能推出「没肉」**——原设计里这条排除规则是错的，已删除。`LB` 只是 M1–M3 这个受限模型下的下界，不是任意重综合的下界。

**局限二：即使在 M1–M3 内，界也很松。** `in=12, out=2, K=6` 时 `LB = max(2, ⌈10/5⌉, …) = 3`，实际可能需要 20 个 LUT。`in ≤ K` 时 `LB = out` 可达（每个输出一个 LUT），但这一档 `if -K` 的 cut 枚举早吃掉了；真正的矿在 `K < in ≤ Imax`，而这一档界最松。

所以 `gap` 在本期只有一个角色：**报表里的一列上下文**，供人工判读，附带 M1–M3 的模型说明。它**不参与排序**、**不作排除**、**不当收益数字对外宣称**。真正的收益测量要靠抽出区域实跑重映射对比 LUT 数，那是下一期（§9）。

## 3. 凸性：正确性硬约束

### 3.1 定义

区域 `R` 必须是**凸的**：不存在「从 `R` 内出发、离开 `R`、再回到 `R`」的路径。否则抽出的子网表无法作为一个整体被替换——外部那段逻辑既要读区域的输出又要给区域喂输入，替换后必然产生组合环。

**这是正确性要求，不是可调项。** 任何报出的区域都必须凸。

凸性在**组合图** `CombGraph` 上定义（§5）。所以「`R` 出去经过一个 latch 再回到 `R`」**不算违规**——latch 已经打断了组合路径，抽出的子网表仍可整体替换。

### 3.2 违规集与最小凸超集

`desc(R)` / `anc(R)` 是在 `CombGraph` 上沿组合边的**传递可达集**，两者都**包含 `R` 自身**（自反传递闭包）。顶点域就是 `CombGraph` 的顶点域：内部节点与 `const1`，遍历在 PI / PO / BI / BO / latch 处终止，这些边界对象不是 `desc` / `anc` 的成员。

节点 `v ∉ R` 是违规点，当且仅当 `v ∈ desc(R) ∩ anc(R)`。由顶点域可知违规点必然是内部节点或 `const1`，也就是**必然是合法的区域成员**——所以最小凸超集总是存在，不会出现「必须吸收一个不可吸收的对象」的死局。

最小凸超集为 `R' = R ∪ V`，其中 `V = desc(R) ∩ anc(R) \ R`。

**一次闭包即到位**（不需要迭代到不动点）：因 `V ⊆ desc(R)`，有 `desc(R') = desc(R)`；同理 `anc(R') = anc(R)`。于是 `R'` 的违规集 `= desc(R) ∩ anc(R) \ R' = ∅`。

这个性质让每次移动的闭包代价可预测，也给出一条可直接断言的测试（二次闭包必须是 no-op）。

### 3.3 搜索范围与预算

违规点搜索用两趟 bitset 扫描（前向 `desc`、后向 `anc`）取交集。

**不能用 `Abc_NtkLevel` 的层号做严格层带剪枝。** `Abc_NtkLevel_rec`（`src/abc/src/base/abc/abcDfs.c:1369`）对 `Abc_ObjIsBarBuf` 节点**不递增层号**，于是 `r1 → v(barbuf) → r2` 里 `v` 可以与 `r1` 同层。此时违规点落在闭层带的**边界上**而非开区间 `(min_level, max_level)` 内，开区间剪枝会漏掉它，直接产出非凸区域。

（这个失效目前是潜在的而非已发生的：`Abc_ObjIsBarBuf` 要求 `Abc_NtkHasMapping`，而 `if -K` 产出的网络是 `ABC_FUNC_AIG`，谓词恒假。但不能把正确性挂在这个巧合上。）

采用的方案：`CombGraph` 自带一个**沿每条组合边严格递增的 rank**——构造时按拓扑序赋值 `rank(v) = 1 + max(rank(fanin))`，与 ABC 的 `Level` 字段无关。违规点必然满足 `min_rank(R) < rank(v) < max_rank(R)`，剪枝在这个 rank 上做，结论成立且不依赖任何 ABC 层号语义。

搜索带**工作量预算**（访问节点数上限，内部常量）。**超预算就拒绝这次移动**，而不是接受一个未验证的区域。这条保守规则可能漏掉好区域，但绝不产出非法区域。

## 4. 生长算法

### 4.1 种子：MFFC

用 MFFC 做种子（`Abc_NodeMffcLabel`，`src/abc/src/base/abc/abcRefs.c:439`，现成可用）。

**MFFC 天然凸。** 证明要小心，不能说成「MFFC 对 fanout 封闭」——那对根 `n` 本身是假的：`n ∈ MFFC(n)`，而 `n` 通常正是驱动着 MFFC 外部节点的那一个（`Abc_NodeMffcLabel_rec` 在 `src/abc/src/base/abc/abcRefs.c:408` 用 `fTopmost` 标志专门放过根的 fanout 检查，非根成员则要求解引用后 `vFanouts.nSize == 0`）。

正确的论证：设存在违规路径 `u → … → w → … → v`，其中 `u, v ∈ MFFC(n)` 而中间节点 `w ∉ MFFC(n)`。分两种情况。若 `u ≠ n`：`u` 是非根成员，解引用后其全部 fanout 都在锥内，故 `u` 无法迈出第一步到锥外，矛盾。若 `u = n`：路径从根出发，而组合图无环且 `n` 是锥内所有节点的必经汇点，故不存在从 `n` 回到任何 `v ∈ MFFC(n)` 的路径，矛盾。两种情况都不可能，故 MFFC 凸。

MFFC 还天然 `out = 1`（只有根有区域外 fanout）。

**种子的可行性检查。** MFFC 可能一开始就超限（`N > M`、`in > Imax` 或 `out > Omax`）。生长循环只会让区域变大，缩不回来，所以这种种子**直接跳过**，不进入生长，也不记入历史最佳——否则报表会输出违反 `-M`/`-I`/`-O` 的区域，跟 §8 的集成断言直接冲突。历史最佳前缀只在通过可行性检查之后才初始化。

种子按 MFFC 规模降序取前 `nSeeds` 个（`-S`，默认 2000；`0` = 全部节点），让运行时间可预测。这个顺序偏好大而居中的锥，可能漏掉别处小而密的团（见 §9 已知局限）。

### 4.2 移动集

每步从两类候选中选一个：

- **入口吸收**：把某个区域外驱动对象 `d` 吃进区域。这是密度增长的主引擎——`d` 消失贡献 `Δin = −1`；`d` 的 fanin 若已在 `in(R)` 或 `R` 内则不引入新输入；同时那些「仅因驱动 `d` 而算 output」的 `R` 内节点会脱去 output 身份。当 `d` 与 `R` 的 fanin 高度重叠时 `Q` 跳升。
  - 候选集是「`R` 的全部区域外驱动对象中，类型为内部节点或 `const1` 的那些」。**注意这不等于 `in(R)` 的成员**：区域外 `const1` 不计入 `in`（§2.1 规则 1）却仍是合法候选。PI、BO（latch 输出）不可吸收。
- **出口吸收**：把 `out(R)` 某个成员的某个 fanout 吃进区域，同样要求该 fanout 是内部节点或 `const1`。用于跨过扇出扇入的沙漏腰。

两类都可能引入违规点（`r ∈ R → v ∉ R → d` 这种重汇聚），所以**都要过凸闭包**。

**边多重性**：所有边界集合（`in`、`out`、候选集）都按**源对象身份**去重。一个节点的 fanin 表里同一个驱动出现两次，只算一个 `in` 成员、一个候选、`CombGraph` 里一条邻接边。边多重性只在 §2.4 的槽位计数里保留（两次读占两个槽）。

### 4.3 每步的候选评估预算

为控制单步成本：先用「假设闭包为空」的乐观增量给全部候选算一个预估 `Q`，排序后只对前 `L` 个（内部常量，默认 4）算真实闭包与真实 `Q`，取其中实际最优者执行。

若前 `L` 个全部不可行（闭包超预算，或闭包后越限），本步无可行移动，终止该种子。

**这个剪枝无质量保证，是本设计已知最弱的一环。** 乐观估值假设闭包为空，而真实闭包既可能变好（吸收一整片重汇聚带，反而消掉好几个边界引脚）也可能变坏。排在第 5 位的候选即使真实 `Q` 全局最优也永远不会被评估——尤其是那些要跨过窄重汇聚腰的移动，恰好是最有价值的一类。本期接受这个损失（先出仪器读数），改进方向见 §9。

### 4.4 非单调爬坡与终止

`Q` 沿生长轨迹**不单调**，所以算法记录**历史最佳前缀**而非终止状态——与 `fmpart` 的 FM best-prefix 同一个道理（`docs/fmpart-design.md`）。

终止条件（任一满足）：

- 连续 `stall` 步（内部常量，默认 8）未刷新历史最佳
- `N(R)` 达到 `-M` 上限
- 无可行移动

**可行性上限**（越限的移动直接判不可行，不执行）：

- `in > Imax`（`-I`，默认 32）
- `out > Omax`（`-O`，默认 8）
- `N > M`（`-M`，默认 64）

上限对**中间状态**生效，不只对最终报告的区域生效。这会让一类区域不可达：某个移动暂时把 `in` 顶过上限、随后几步吸收又把边界收回来的路径。本期接受（实现简单、行为可预测），代价记在 §9。

最终输出该种子的历史最佳区域；若该种子没有任何通过可行性检查的状态（见 §4.1），则不产出候选。

### 4.5 近重复抑制

多个种子会长到高度重叠的区域。全部种子收敛后，按 `Q` 降序扫描候选，若某区域与任一已接受区域的 Jaccard 重叠 `|A∩B| / |A∪B|` 超过阈值（内部常量，默认 0.5）则丢弃，否则接受。取前 `-N` 个。

这样报表里的 N 条是 N 个真正不同的热点，而不是同一个团的 N 个抖动版本。

### 4.6 复杂度

每步的成本有两块，候选枚举排序不能省略不计：

```
每步：O(C log C + L × 闭包预算)      C = 该步的候选数
每种子：O(M × (C log C + L × 闭包预算))
```

`C` 的坏情况不小：`out(R)` 里有个高扇出节点时 `C` 可以到 `Θ(|V|)`，于是单个种子退化成 `Θ(M·|V|·log|V|)`，即使闭包预算很小也一样。缓解办法是候选枚举**对每个 `out` 成员的 fanout 取样上限**（内部常量），把 `C` 压成 `O(in + out × fanout_cap)`；排序改用 `nth_element` 选前 `L` 个，省掉 `log C`。

全局线性于种子数。全程只读网表结构。

## 5. 模块划分

`src/hive/`，按「最有风险的部分单独可测」切分：

| 文件 | 职责 | 依赖 |
|---|---|---|
| `hive.hpp` | `Config`、`RegionReport`、`ApplyHive` 公开接口 | — |
| `hive_graph.{hpp,cpp}` | `CombGraph`：组合图快照。顶点域、去重邻接、严格递增 rank | ABC |
| `region.{hpp,cpp}` | `Region`：成员 bitset + `in`/`out` 集合的增量维护 + `Q` / `LB` / `gap` 计算 | `CombGraph` |
| `convex.{hpp,cpp}` | 凸闭包：rank 带内违规点搜索、预算控制、最小凸超集 | `CombGraph` |
| `hive.cpp` | MFFC 种子、生长循环、Jaccard 去重、Top-N、报表打印 | 以上全部 |

`convex` 单独成 TU，因为它是**唯一的正确性关键路径**：其他部分是启发式，错了只是结果差；它错了会产出无法使用的非法区域。

`CMakeLists.txt` 照 `src/pdecomp/CMakeLists.txt` 的模式（`add_library`，链 `libabc`），并在 `src/CMakeLists.txt` 里 `add_subdirectory(hive)` + 加进 `FoxSYN` 的 `target_link_libraries`。

### 5.1 `CombGraph` 的精确规格

这是全模块的地基，语义必须无歧义。

**顶点域**：内部节点（`Abc_ObjIsNode`）与 `const1`。PI、PO、BI、BO、latch **不是顶点**。

**latch 截断**（ABC 用 latch box + BI/BO 三个对象表示一个状态元件；`abc.h:363-364` 里 `Abc_ObjIsCi` 含 BO、`Abc_ObjIsCo` 含 BI）：

- 反向遍历遇到 BO 即停。**BO 是 `in` 的合法成员**（它是区域的一个外部源）。
- 正向遍历遇到 BI 即停。**驱动 BI 的区域内节点计入 `out`**。
- 两个方向都**不得穿过 latch box** 从 BI 走到 BO 或反向。这条是 §3.1「latch 打断组合路径」的实现保证。

**邻接去重**：`CombGraph` 存的是**去重后的**前驱/后继集合（见 §4.2 边多重性）。原始 fanin 表的多重性只在 §2.4 槽位计数时另行读取，不体现在邻接里。

**rank**：构造时按拓扑序赋 `rank(v) = 1 + max(rank(u))`（`u` 为 `v` 在 `CombGraph` 里的前驱，无前驱则 `rank = 0`）。沿每条边严格递增，与 ABC 的 `Level` 字段无关（理由见 §3.3）。

**快照语义**：构造一次，之后不跟随网表变化（`hive` 只读，网表本来也不变）。这与 `fmpart` 的 `AbcNtkWrapper` 一致。

实现侧已确认：`Abc_Ntk_t` 的 fanout 列表默认维护（`src/csr/csr.cpp` 直接用 `Abc_ObjForEachFanout`，无需额外初始化），所以 `out(R)` 与向前生长都能 O(1) 查邻居。

## 6. 命令接口

```
hive [-N num] [-M num] [-I num] [-O num] [-K num] [-S num] [-v]
```

| 选项 | 含义 | 默认 |
|---|---|---|
| `-N num` | 报告的区域数 | 20 |
| `-M num` | 区域节点数上限 | 64 |
| `-I num` | 输入数上限 `Imax` | 32 |
| `-O num` | 输出数上限 `Omax` | 8 |
| `-K num` | LUT 宽度（仅用于 `LB` 计算） | 6 |
| `-S num` | 种子数上限，`0` = 全部节点 | 2000 |
| `-v` | 逐区域打印节点列表与边界对象 id | off |

合法取值范围（越界即报错退出）：`-N ≥ 1`；`-M ≥ 1`；`-I ≥ 1`；`-O ≥ 1`；`-K` 在 `2..16`；`-S ≥ 0`。

`L`（每步实算候选数 4）、`stall`（8）、Jaccard 阈值（0.5）、闭包访问预算均为**内部常量**，本期不暴露——先测量阶段没有调参需求，需要时再加选项。

参数解析照 `Pdecomp_Command`（`src/main.cpp:1059`）的 `switch` + `goto usage` 风格。注册到 `"FoxSYN"` 命令组。

### 前置条件

- 当前网络存在
- `Abc_NtkIsLogic(pNtk)` 为真
- **不要求 `pPdb`** —— 这是 `hive` 与 `csr` / `pdecomp` 的关键区别，它不消费分区信息

latch 允许存在（当边界处理）。

### 只读性与错误处理

**只读的确切含义**：不修改网表的**结构**（对象、fanin/fanout 关系、`pData`），不写 `Pdb`。

允许的副作用只有两类缓存字段：travId（`Abc_NodeMffcLabel` 内部会递增并打标记），以及 `Abc_NodeDeref_rec` / `Abc_NodeRef_rec` 在 MFFC 计算过程中对 `vFanouts.nSize` 的临时增减（`Abc_NodeMffcLabel` 保证配对还原，见 `abcRefs.c:443-449` 的 `assert(Count1 == Count2)`）。

`hive` **不调用 `Abc_NtkLevel`**，所以不碰 `Level` 字段——rank 存在 `CombGraph` 自己的数组里（§3.3、§5.1）。这既是正确性需要，也顺带保住了「除缓存字段外无副作用」这句话的成立。

- 前置条件不满足：打印原因，返回失败
- 网络无内部节点：打印提示，**正常返回**（不算错误）
- 参数越界（如 `-K` 不在 2..16、`-N` < 1）：打印原因，返回失败

## 7. 报表格式

```
hive: 4213 nodes, K=6, 2000 seeds
  #  root      N   in  out     Q    LB   gap  lvl
  0  n0873    38    9    2   3.45    2    36    5..11
  1  n1245    47   11    3   3.36    3    44   12..19
  ...
hive: 20 regions, 612 distinct nodes (14.5% of netlist), Q in [1.82, 3.45]
```

区域按 `Q` 降序排列。上面两行也演示了 §2.5 的诚实交代：`gap` 大到 36 / 44 只说明**下界很松**，不代表真能省掉那么多 LUT。

`root` 是种子节点名。`lvl` 是区域的 rank 范围（`CombGraph` 的 rank，见 §5.1，不是 ABC 的 `Level`）。`-v` 追加每个区域的成员节点 id 列表与 `in` / `out` 对象 id 列表。

报表头部另打一行 `gap` 的模型说明，避免读者把它当收益：

```
hive: gap is against LB under model M1-M3 (structural-pin-preserving, LUT-only);
      it is NOT a lower bound for functional resynthesis -- see docs/hive-design.md 2.5
```

## 8. 测试策略

`src/test_hive.cpp`，手写断言，照 `src/test_fmpart.cpp` 的 `ExpectEq` / `ExpectTrue` 风格（本仓库无测试框架），在 `src/CMakeLists.txt` 里加 `add_executable(test_hive ...)`。

### 单元断言

**`CombGraph`（§5.1）**

- 顶点域：PI / PO / BI / BO / latch 均不是顶点；内部节点与 `const1` 是
- latch 截断：正向不从 BI 穿到 BO，反向不从 BO 穿到 BI；BO 可作 `in` 成员；驱动 BI 的节点计入 `out`
- 邻接去重：fanin 表 `[a, a]` 在 `CombGraph` 里只产生一条邻接边
- rank 严格递增：每条边都满足 `rank(dst) > rank(src)`。**再断言这一点不依赖 ABC 的 `Level`**——构造一个一 fanin、`pData == NULL` 的节点（`Abc_ObjIsBarBuf` 的形状），断言其 `rank` 严格大于驱动者，即使 `Level` 相等

**边界计数（§2.1、§2.2）**

- 一个 driver 供 3 条 fanin 边只算 1 个 `in`
- 驱动 PO 的节点计入 `out`
- 区域外 `const1` 不计入 `in`，但**出现在入口吸收候选集里**（§2.1 规则 1+2 的联合断言，这是原设计的矛盾点）
- 区域内 `const1` 即使有区域外 fanout 也不计入 `out`（规则 3）
- 一个节点同时有区域内和区域外 fanout：只算 1 个 `out`；吸收其部分区域外 fanout 后仍是 `out`；**全部** fanout 进区域后才脱去身份
- 增量 vs 重算：随机生长若干步后，断言增量维护的 `in`/`out`/`N`/`Q`/`LB` 与从头重算完全一致

**凸闭包（§3.2、§3.3）**

- 单个 `r1 → v → r2` 重汇聚：断言 `v` 被吸收
- **链式/嵌套违规点**：多条不同长度的违规路径、多对源汇，断言一次闭包结果 == 反复闭包结果 == 独立暴力可达性壳
- rank 带剪枝与完整检查**必须找到同一个违规集**：包括违规点 rank 恰好等于区域端点 rank 的用例，以及 barbuf 形状节点在违规路径上的用例
- latch 截断路径：出区域经 latch 再回区域，断言**不**被判违规
- 闭包预算超限：断言移动被拒绝，且区域状态（成员、`in`/`out`）逐字段未变

**生长与可行性（§4.1、§4.3、§4.4）**

- 种子超限（`N > M` / `in > Imax` / `out > Omax`）：断言该种子被跳过，不产出候选
- MFFC 种子：根有多个区域外 fanout 且含重汇聚路径时，断言凸且 `out == 1`
- 入口吸收与出口吸收各自的增量正确性
- 最优候选排在乐观序第 5 位：断言**当前实现确实错过它**（把 §4.3 的已知损失钉成回归基线，而不是假装没有）
- best-prefix：`Q` 中途见顶随后下降，断言报出峰值区域；谷长 > 1 步的轨迹也要覆盖
- 中间状态超限的路径被拒绝（§4.4 的已知取舍，同样钉成基线）

**`LB`（§2.4、§2.5）**

- 三项 `max` 各自当选的手算例子
- `(in − out) ≤ 0` 时第二项取 0，不出现负数或错误 ceiling
- 重复 fanin、既是输出又被内部消费的节点、区域内外 `const1`：断言界仍成立（只是更松）
- `out = 0` 与 `in < K` 的退化情形
- **功能冗余反例**（§2.5 局限一）：构造那个 `x = LUT(a,b)` 忽略 `b` 的例子，断言 `LB = 2` 而真实功能只需 1 个 LUT。这条测试的作用是把「`LB` 不是功能性下界」固化成可执行文档，防止后人误加 `gap ≤ 0` 的排除逻辑
- 小 DAG 穷举：在 M1–M3 模型下枚举小图，断言 `LB ≤ 真实最优 m`

**Jaccard 去重（§4.5）**：两个高度重叠的区域，断言只留 `Q` 更高的那个

**错误路径（§6）**：无网络、非 logic 网络、无内部节点（正常返回）、各参数越界

### 集成 + 交叉验证

在 `regression/SimpleCircuits` 的 `alu4` 与若干 EPFL 用例上跑 `hive`，对**每个报出的区域**用一个**独立的暴力凸性检查器**（完整可达性计算，与增量闭包完全不同的代码路径）验证凸性，并断言：

- `in ≤ Imax`、`out ≤ Omax`、`N ≤ M`
- `LB ≤ N`
- 所有成员都是合法区域成员（内部节点或 `const1`）
- 报出区域两两 Jaccard ≤ 阈值
- 报表里的 `in`/`out`/`N`/`Q`/`LB`/rank 带与独立重算值一致
- 运行前后网表结构与 `Level` 字段逐对象未变（§6 只读性）

暴力检查器是这套测试的重心：启发式的质量看报表就能判断，**凸性必须由第二条独立代码路径证实**。

## 9. 已知局限与后续方向（本期不做）

本期是测量仪器，刻意接受下列损失。每条都在 §8 里有对应测试把当前行为钉成回归基线，避免它们被误当成 bug 修掉、或被遗忘。

**搜索质量（贪心的固有损失）**

- **乐观 top-`L` 剪枝无质量保证**（§4.3）。改进方向：小区域上全量评估；给真实 `Q` 找一个可采纳的上界做剪枝；`L` 随候选数自适应；或保留 beam 而非单条贪心路径。
- **上限对中间状态生效**（§4.4），排除了「先超限再收回」的路径。改进方向：有界前瞻，或区分「中间超限」与「最终报告超限」。
- **`stall = 8` 可能提前终止**长于 8 步的下坡后回升序列。
- **MFFC 规模降序的种子偏置**（§4.1）偏好大而居中的锥。改进方向：按 rank / 扇出分层取样或随机取样补充种子。
- **Jaccard 去重的顺序依赖**（§4.5）：按 `Q` 贪心接受，可能丢掉一个 `Q` 略低但覆盖显著更广的区域。本期作为明确策略接受；若覆盖率重要，可加次级 tie-breaker。

**度量局限**

- **`LB` 不是功能性重综合的下界**（§2.5 局限一）。这是本设计最重要的诚实交代：`gap` 只是报表上下文，不能用作排除。
- **真实 gap 测量**：把候选区域抽成独立子网表，跑 `collapse` / `ttopt` / `if -K` 重映射，对比 LUT 数，得到真收益。这是决定后续投入的关键数据，也是 §1「非目标」里那条的正式立项入口。

**功能扩展**

- **下游对接**：确定消费引擎后，为其定制 `Imax` / `Omax` 并输出对应格式（真值表类要求 `in ≤ 16`；结构重综合类可放宽）。
- **局部 refinement**：边界剥离（把拉低 `Q` 的边缘节点吐出来）、多起点重启。
- **与 `fmpart` 协同**：把「团」当作不可分割单元喂给划分器，避免划分把一个可优化的团切开。呼应 `docs/csr3.md` §12.5 的「划分器协同」。

## 评审记录

2026-08-08：本 spec 经 codex (`gpt-5.6-sol`) 独立技术评审，修正了 5 处会导致实现出错的问题：

1. **§3.3 层带剪枝不成立** —— `Abc_NtkLevel_rec`（`abcDfs.c:1369`）对 barbuf 不递增层号，违规点可与区域端点同层，开区间剪枝会漏判并产出非凸区域。改为 `CombGraph` 自带的严格递增 rank。
2. **§2.5 `gap` 不能作排除性筛子** —— `LB` 依赖「结构输入必须被读」，而功能性重综合恰可证明输入冗余。原「`gap ≤ 0` 铁定没肉」是错的，已删除并补上反例。
3. **§2.1/§4.2 `const1` 自相矛盾** —— 原文允许吸收 `const1` 但候选集定义为 `in(R)` 的成员，而区域外 `const1` 不计入 `in`，导致永远选不中。
4. **§4.1 MFFC 凸性证明有误** —— 「MFFC 对 fanout 封闭」对根节点为假（`abcRefs.c:408` 的 `fTopmost` 正是放过根的 fanout 检查）。已换成分根/非根两种情况的正确论证。
5. **§4.1 种子可能一开始就超限** —— 原文未规定跳过，会输出违反 `-M`/`-I`/`-O` 的区域。

另补全了 §2.4 的实现模型 M1–M3、§5.1 的 `CombGraph` 精确规格（latch BI/BO 截断、邻接去重）、§4.6 的候选枚举成本、§6 的只读性确切含义，并把 §8 的测试扩到覆盖上述每条断言。

未采纳的建议：beam search 替代贪心、复杂度与种子数标度的自动化测试——本期是测量仪器，这些属范围外，已记入 §9 已知局限。
